# First-run app tour — October 20, 2026

> Historical report: findings below describe the dated run and are retained as evidence. Product: **TaxTech — AI-Assisted Withholding Tax Preparation**. The demo uses FY2024–25 (Tax Year 2025). Tax constants can be modified for any tax year together with its applicable rules and effective dates, followed by validation before activation. See [tax-year configuration](tax-year-configuration.md) for the required changes and current limits.

A six-step guided tour appears automatically when an eligible signed-in account first opens the workspace. It introduces the dashboard, ledger upload, AI-assisted review, supplier evidence, tax batches, summaries/reconciliation and help. Viewers receive read-only wording. The tour waits until an enforced legacy password change is complete.

Next and Back move through the steps. Skip, Escape and the close control dismiss it. Finish closes the final step. Optional page shortcuts close the tour and open the relevant page. **App tour** in the top bar reopens it from the beginning at any time, including on mobile.

The first displayed tour is recorded per account on the server using an `APP_TOUR_SEEN` audit record, so the preference survives later sign-ins and other browsers/devices. It is not a shared browser-local flag. Repeated or simultaneous calls are idempotent through a transaction-scoped advisory lock. No schema migration, new account, paid service or AI request is required. The tour itself only explains the app; it never uploads, approves, calculates, pays or files anything.

The preference endpoint authorizes independently and takes identity only from the session. Viewers may save their own tour preference without gaining financial write permissions. Anonymous, foreign-origin and legacy-password-restricted requests remain blocked. If saving the preference fails, the tour remains usable and a notification explains that it may appear again next time.

The UI uses the existing accessible dialog primitive, with title/description association, standard focus/close behavior and a step-status announcement. Its content scrolls within the viewport on small screens. No new animation library was added.

The account-persistence integration passed its behavior checks: first visit, fresh-session persistence, concurrent idempotence, separate-user preferences, viewer permissions, password-change precedence and request-access protections. The replay entry remained available after the preference was saved. The isolated server was stopped after testing; the main local server remains running with the new bundle.

`tests/app-tour.integration.ts` uses separate synthetic accounts in the isolated `install_*` database on localhost:3002. It checks the layout's first-run flag, persistence across fresh sessions, concurrent idempotent saves, per-user separation, a replay entry after dismissal, viewer access without financial-write escalation, legacy password precedence, and anonymous/foreign-origin rejection. It does not pretend an HTTP response is an interactive browser test. Private diagnostics are `/tmp/taxtech-app-tour-results.json`.
